# 案件複製機能：本番環境での安全な手動テスト手順（未実行）

このドキュメントは手順の準備のみを目的としており、記載内容はまだ実行していません。
実行は必ずユーザーの承認後に行ってください。

## 前提・安全条件

- テスト案件名は以下に統一する
  - 元案件：**「【複製機能テスト】削除予定」**
  - 複製先（一覧経由）：**「【複製機能テスト】削除予定（コピー）」**
  - 複製先（詳細経由）：**「【複製機能テスト】削除予定（コピー2）」**
- 本番の実顧客案件・実データは一切操作しない
- **Googleカレンダーへの実際の予定作成・登録操作は一切行わない**（「Gカレンダー」ボタンは押さない）
- `gcal_event_id`へ任意の文字列（`'registered'`等）を手動で入れる操作は行わない。この列はGoogleの正式なイベントIDを扱う列のため、テスト目的であっても実値以外を入れない
- テストで作成したデータは、確認完了後に**すべて削除**する
- 各ステップの実行前後で、対象が本番の重要案件と混同されていないか目視確認する

## GoogleカレンダーID（gcal_event_id）の確認方法

- 元案件・複製先ともに`gcal_event_id`は**NULLのまま**にする（手動で値を入れない）
- 複製操作の前後で、Googleカレンダー側に新しい予定が作成されていないことを確認する（Googleカレンダーを開いて目視、または何も操作していないため作成されるはずがないことをコードレビューで確認済みの前提を再確認する）
- 複製先の`gcal_event_id`もNULLのままであることを確認する（＝複製元がNULLなら複製先もNULL、複製元に値があっても複製先はNULLに初期化される、のどちらも実質NULL→NULLの確認になる）

## 手順

1. **テスト案件を新規作成**
   - 案件名を「【複製機能テスト】削除予定」に設定する
   - 開催日・時間（搬入/リハ/開演/終了/完全撤収）・階・連絡方法などを適当なテスト値で入力する
   - `gcal_event_id`はNULLのまま（Googleカレンダー登録操作は行わない）

2. **オプションを最低1件追加**
   - ⑤備品・設備または⑥機材・オペレーターのいずれかに、テスト用の1件を追加する

3. **飲食プランを最低1件追加**
   - ④飲食プランにテスト用の1件を追加する

4. **見積金額をテスト用の値に設定**
   - 例: ¥12,345 のような、実際の見積もりと混同しない値にする

5. **支払い・請求・申込みフォーム・搬入出届を「対応済み」に変更**
   - `deposit_status`（申込み金）、`remaining_payment_status`（残額支払い）、`invoice_status`（請求書）、
     `application_form_status`（申込みフォーム）、`delivery_notice_status`（搬入出届）をすべて「済み」系の値に変更する
   - 下見日時（`preview_datetime`）にも適当なテスト値を入力し、下見済みフラグが立つ操作があれば行う
   - これにより、複製後にすべて初期化されていることを確認できる状態を作る

6. **一覧から複製**
   - 案件一覧の「【複製機能テスト】削除予定」の行にある複製アイコンをクリックする
   - 確認ダイアログの文言を確認し、「複製する」を押す
   - 複製後、編集画面へ遷移することを確認する
   - 案件名が「【複製機能テスト】削除予定（コピー）」になっていることを確認する
   - 成功通知（「案件を複製しました。案件名と開催日を確認してください。」）が表示されることを確認する

7. **詳細から複製**
   - 手順1の元案件（または手順6の複製先）の詳細画面を開き、「複製」ボタンから同様に複製する
   - 案件名が「【複製機能テスト】削除予定（コピー2）」になることを確認する
   - 同様に編集画面への遷移・成功通知を確認する

8. **スマホ表示での複製ボタン確認（新しい案件は作成しない）**
   - スマホ幅（実機、または開発者ツールのデバイスモード）で案件一覧を開く
   - 「【複製機能テスト】削除予定」カード（元案件）の複製アイコンをタップする
   - タップ直後に**詳細画面へ誤遷移していないこと**を確認する
   - 確認ダイアログが開くことを確認する
   - **「キャンセル」を押す**
   - 一覧・Supabase側の両方で、新しい案件（（コピー3）等）が作成されていないことを確認する
   - この手順では既存の3案件（元・（コピー）・（コピー2））以外は一切作成しない

9. **複製元と複製先を比較**

   | 項目 | 複製元（【複製機能テスト】削除予定） | 複製先で期待する値 |
   |---|---|---|
   | 案件名 | 【複製機能テスト】削除予定 | （コピー）/（コピー2）が正しく連番になっている |
   | 開催日 | 入力済み | 空欄 |
   | 開催時間（搬入/リハ/開演/終了/完全撤収） | 入力済み | 複製元と同一の値が引き継がれている |
   | 見積金額 | テスト値 | 0 |
   | ステータス | 手順1〜5で変更した値 | inquiry（新規問合せ、正式な初期値） |
   | 申込み金/残額支払い/請求書/申込みフォーム/搬入出届 | 済み系 | すべて未対応 |
   | 下見情報（preview_datetime, has_previewed） | 入力済み/true | NULL/false に初期化されている |
   | GoogleカレンダーID | NULL | NULL（Googleカレンダーに新しい予定が作成されていないことも確認） |
   | オプション・飲食プラン | 手順2・3で追加した内容 | 同じ内容が複製されている |
   | 添付ファイル・確認事項（チェックリスト）・仮押さえ履歴・案件履歴 | 元案件の状態 | 複製先には一切複製されていない（空） |
   | 元案件自体の内容 | — | 複製操作の前後で一切変化していないこと |
   | 複製後の画面遷移 | — | 一覧・詳細どちらの操作でも編集画面へ遷移していること |

10. **作成したテスト案件をすべて削除**
    - 手順1・6・7で作成したすべてのテスト案件（元＋複製2件）を、詳細画面の「削除」ボタンから削除する
    - 案件一覧・Supabaseダッシュボードの両方で、テストデータが残っていないことを確認する

- 本番の実顧客案件に対する複製操作
