## マイグレーション適用

1. テスト用Supabaseプロジェクトの SQL Editor で [`supabase/migrations/20260805_add_confirmed_at.sql`](../supabase/migrations/20260805_add_confirmed_at.sql) を実行する
2. 実行後、`cases`テーブルに`confirmed_at`列（TIMESTAMPTZ、NULL許容）が追加されていることを確認する

## テストA：通常の編集が壊れていないこと（最優先）

この機能は全案件の保存処理に手を入れているため、**ステータス以外の項目だけを編集する保存が今まで通り動くこと**を最優先で確認します。

1. テスト案件を新規作成する（ステータスは「新規問合せ」のまま）
2. 会社名・担当者・見積金額など、ステータス以外の項目を編集して保存する
3. 保存が成功し、編集内容が正しく反映されることを確認する
4. `confirmed_at`が`NULL`のままであることを確認する（Supabaseダッシュボードで確認）
5. 上記を3回程度繰り返し、毎回問題なく保存できることを確認する

## テストB：ステータス遷移パターン別の`confirmed_at`挙動

| # | 遷移 | 操作 | 期待結果 |
|---|---|---|---|
| B1 | 新規問合せ→確定 | ステータスを「確定」に変更して保存 | `confirmed_at`が現在時刻でセットされる |
| B2 | 確定→確定（他項目のみ編集） | ステータスは「確定」のまま、見積金額だけ変更して保存 | `confirmed_at`が**変化しない**（再スタンプされない） |
| B3 | 確定→キャンセル | ステータスを「キャンセル」に変更（キャンセル理由も入力） | `confirmed_at`は**そのまま残る**（クリアされない） |
| B4 | キャンセル→確定（再確定） | B3の案件を再度「確定」に変更 | `confirmed_at`が**新しい時刻に上書き**される |
| B5 | 新規問合せ→終了（confirmedを飛ばす） | ステータスを直接「終了」に変更 | `confirmed_at`がセットされる（確定を経由しなくても動作すること） |
| B6 | 新規作成時に最初から「確定」で登録 | 新規登録フォームでステータスを「確定」にして保存 | 作成直後から`confirmed_at`がセットされている |

各テストとも、Supabaseダッシュボードで`cases`テーブルの該当行を直接確認してください。

## テストC：認知経路タブの月別内訳

1. テストBで作成した案件（媒体を設定しておく）を使い、案件一覧 →「分析・集計」→「認知経路」タブを開く
2. 既存の年間集計表（画面上部）が今まで通り表示されることを確認する（レイアウト崩れがないこと）
3. その下に追加された「認知経路別 月別内訳」を確認する
   - 「問合せ」「下見」「確定」の切り替えボタンが機能すること
   - 問合せ件数：案件の問合せ日の月に正しく計上されていること
   - 下見件数：下見日時を入力した案件が、その月に正しく計上されていること
   - 確定件数：テストB1で確定させた月に正しく計上されていること。B3でキャンセルした案件は確定件数に**含まれない**ことを確認する
4. 「確定」タブ選択時に、注記（「確定日時記録の導入日以降のみ正確に集計されます」）が表示されることを確認する
5. 年度セレクタを変更し、他の年を選んでもエラーなく表示が切り替わることを確認する

## テストD：スマホ表示

1. スマホ幅（開発者ツールのデバイスモード、または実機）で「分析・集計」ページを開く
2. 「認知経路」タブの月別内訳テーブルが横スクロールで閲覧できること、レイアウトが崩れていないことを確認する
