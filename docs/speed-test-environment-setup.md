# 保存後速度改善：テスト環境セットアップ手順書

この手順は、本番環境・本番Supabase・顧客データに一切触れずに、
案件保存後の画面遷移速度改善を安全に検証するためのものです。

## 前提

- この手順はすべて**ユーザー側（社内の担当者）**が実施してください
- Claude Codeはこの手順の実行（Supabase接続・アカウント作成・ログイン・デプロイ・データ操作）を行いません
- 本番用の `apexia-app-fixed` フォルダと、テスト用の別作業フォルダは**完全に分離**してください

## 手順

### 1. テスト専用Supabaseプロジェクトの作成

1. supabase.com のダッシュボードで、本番プロジェクトとは別に**新規プロジェクト**を作成する
   （プロジェクト名は「apexia-test」など、本番と明確に区別できる名前を推奨）
2. 作成後、Project Settings → API から以下を控える
   - Project URL
   - anon / public キー
   - （本番と異なることを目視で必ず確認する）

### 2. スキーマの適用

1. 本番リポジトリの `supabase/migrations/` フォルダ内の全SQLファイルを、
   作成順（`001_〜` から `20260530_〜` まで）にテストプロジェクトのSQL Editorへ貼り付けて実行する
2. 続けて `supabase/seed/99_speed_test_dummy_cases.sql` を実行する
   - このファイルには架空の会社名・氏名・連絡先のみが含まれます
   - 実行後、末尾の確認クエリで3件のテストケースが登録されたことを確認する
3. 必要であれば `scripts/import-master-seed.sql` も実行し、媒体・連絡方法等のマスタデータを投入する（任意）

### 3. テスト用アカウントの作成

1. テストプロジェクトの Authentication 画面から、以下3種類のアカウントを作成する
   - admin用（例: `admin-test@example.test` のような架空アドレス）
   - staff用（例: `staff-test@example.test`）
   - viewer用（例: `viewer-test@example.test`）
2. 各ユーザーの `user_metadata` に `role` を設定する（`admin` / `staff` / `viewer`）
3. パスワードは社内の安全な方法（パスワードマネージャー等）で管理・共有し、チャットには貼らない

### 4. テスト専用の別作業フォルダを用意

1. 本番用フォルダとは別の場所に、リポジトリをもう一つ用意する（clone またはコピー）
2. `env.test.example` をそのフォルダにコピーし、ファイル名を `.env.local` に変更する
3. 手順1で控えたテスト専用Supabaseの値を、その `.env.local` に記入する
   - `NEXT_PUBLIC_APP_URL` はローカル起動なら `http://localhost:3000` などでよい
4. **本番用フォルダの `.env.local` には一切触れない**

### 5. 起動と確認

1. テスト用フォルダで `npm install` → `npm run dev` を実行する
2. ブラウザで `http://localhost:3000` にアクセスし、テスト用アカウントでログインする
   （ログイン操作はユーザー側で行ってください）
3. 案件一覧に、手順2で投入した「テスト株式会社Alpha / Beta / Gamma」が表示されることを確認する

### 6. Claude Codeへの引き継ぎ

以下の情報だけをチャットで共有してください（URL・キー本体は不要です）。

- テスト用アプリURLが本番と異なること（例: 「localhost:3000で起動、本番はhttps://…」）
- テスト用Supabaseプロジェクト名・IDが本番と異なること
- テスト用アカウントへのログインが完了している状態かどうか

上記が確認できた時点で、A〜Gの実機テスト（保存後の遷移・Network計測など）を再開します。
